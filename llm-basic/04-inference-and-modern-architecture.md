# 推理与现代 LLM 架构

> [!important] 一句话核心
> LLM 推理是逐 token 的概率采样；现代架构用 KV cache、GQA/MQA、MoE 和推测解码改善成本或吞吐，但不会把概率模型变成确定性服务，也不会自动提高你任务上的事实可靠性。

## 从 logits 到输出：采样是行为的一部分

模型对下一个 token 给出分数分布，运行时再按配置选择 token。常见参数的直觉：

| 参数 | 做什么 | Agent 含义 |
|---|---|---|
| **temperature** | 缩放分布尖锐程度；更低通常更集中，更高通常更多样 | 低温可减少格式/分类波动，但不能保证正确或消除模型版本差异 |
| **top-p** | 只从累计概率达到阈值的候选集合采样 | 在保留动态候选集的同时限制低概率尾部；仍需以实际任务 eval 调整 |
| **top-k** | 只保留概率最高的固定数量候选 | 也是限制采样空间的手段；不同实现与参数组合有不同效果 |
| **seed/确定性选项** | 尝试提高重放性 | 服务端、模型快照、并行计算与工具状态仍可能带来差异；不能当证明 |

对于抽取、路由和 tool 参数，优先用原生 schema、校验和重试/降级，而不是只调低 temperature。对于创作、候选探索和多方案规划，多样性才是明确价值。

## MoE：大容量，不代表每次都全量计算

**Mixture of Experts（MoE）**把某些 FFN 层替换为多个 expert，再由 router 为每个 token 选择少数 expert 执行。这样模型可拥有更大总参数容量，同时每 token 激活的计算量小于全部 expert 都运行的稠密模型。

| MoE 的特点 | 工程上的正确理解 |
|---|---|
| 稀疏激活 | 总参数量与每 token 计算量可以分离，但实际效率仍受服务实现影响 |
| token 级路由 | expert 不是可解释、可审计、能独立调用的“多个 Agent” |
| 负载均衡需求 | 路由、容量溢出和跨设备通信会增加训练与部署复杂度 |
| 大容量潜力 | 不应从“是 MoE”直接推断它更快、更便宜或更适合你的任务 |

## 推测解码：用额外模型换取更少的目标模型轮次

推测解码通常由较快的 draft model 一次提出多个 token，再由目标模型并行验证、接受或修正。若实现满足算法条件，接受/拒绝机制可以保持目标模型的采样分布；若 draft 预测常被接受，端到端生成会更快。

它主要是**延迟/吞吐优化**，不是让答案更聪明或更可靠。对 Agent 产品，仍应测量真实首 token 时间、流式速度、长输出、工具等待和总体完成时间。

## 延迟与成本的系统视角

用户体验由多个阶段组成：排队、输入预填充、模型首 token、逐 token 输出、工具 I/O、验证、重试与人工等待。只优化“模型每秒 token”可能没有改善端到端任务时间。

| 观察到的问题 | 优先怀疑 | 常见工程杠杆 |
|---|---|---|
| 首 token 很慢 | 长 context、排队、缓存未命中 | 缩短/缓存稳定前缀、检索筛选、拆分任务 |
| 输出很慢 | 自回归输出过长、模型规格 | 限制输出契约、流式展示、路由小模型处理简单步骤 |
| 成本高 | 输入重复、无效重试、过强模型处理全部步骤 | context 去重、缓存、模型路由、先做确定性筛选 |
| 结果不稳定 | 采样、含糊任务、模型/工具变化 | 固定 eval 条件、schema、明确未知值、分层验证 |

## 对 Agent 的直接含义

- **把模型配置纳入版本化**：模型 ID/快照、采样参数、max output、tools/schema 都影响行为；只给 prompt 版本化不够。
- **按子任务路由，而非按“模型名声”路由**：分类、抽取、长上下文综合、复杂规划和高风险复核可有不同质量/延迟/成本要求。
- **为失败留预算**：窗口和时间预算要包含 schema 修复、tool 结果、重试和最终用户回答，不能刚好填满理论上限。
- **先测端到端**：当工具 I/O 占主导时，换更快模型未必值得；当模型输出主导时，减少冗余推理循环通常更有效。

## 常见误解

- **“temperature=0 就完全确定。”** 它最多使采样更贪心/集中；服务、版本、浮点和上下文差异仍可能改变输出。
- **“MoE 是多个 Agent 投票。”** expert 是模型内部的神经网络子模块，不是可解释、可审计的独立专家。
- **“推测解码改变模型能力。”** 它的目标是更快获得目标模型本会产生的分布样本。
- **“长 context 的成本只发生在输入。”** 首 token、KV 内存、并发容量和后续工具/输出预算都受到影响。
