# 视频输入与多模态融合

> [!important] 一句话核心
> 多模态模型不会直接“看一段视频”；系统会把画面、音频、字幕和 OCR 转成某种 token/表示后再与文本融合。输入预处理和融合方式决定了模型实际能观察到什么，也决定了大量失败边界。

## 视频理解的真实输入链

视频文件首先经由抽帧/镜头切分得到画面，经由音频提取和 **ASR** 得到语音转写；鸣笛、碰撞、警报等非语音线索需要**音频事件检测**。画面进入视觉编码器，由 patch 或时空 patch 形成 visual tokens，OCR、检测/跟踪等工具也可提供额外证据。最后，视觉表示、音频表示或转写、字幕和工具结果通过投影、cross-attention 或统一 token 序列与语言模型融合，语言模型才按任务生成结论。

这不是唯一架构，而是应用侧必须问清的事实链。某个“支持视频”的 API 可能只抽取有限帧，可能不读取音轨，可能要求你先上传字幕，也可能隐式完成部分预处理。没有明确的模型/API 文档和实测，不可假定它天然看到了所有模态。

## 视觉编码器：从图像到 visual token

**ViT（Vision Transformer）**把图像切为固定大小的 patch，将每个 patch 映射为向量后用 Transformer 建模。这样视觉内容可以变成类似文本 token 的序列。分辨率越高、patch 越小，潜在细节越多，但 visual token 数、计算与成本通常也更高。

**CLIP**以图文配对数据学习图像与文本的共同表示空间，支持图文相似度和零样本分类等能力。它帮助理解“图像可被映射到语言相关表示”，但不等于任何多模态 LLM 都使用 CLIP，或都拥有同样的 OCR、空间、计数和时间能力。

> [!warning] visual token 不是像素的无损副本
> patch 化、缩放、压缩和视觉编码会丢失细小文字、远处物体、遮挡关系或高频动作。模型对图像的自然语言回答不能替代原始像素、专用 OCR、检测或测量工具。

## 视频原生时序表示

视频不一定是“逐帧图像喂给 LLM”。一些模型把相邻帧组成 **tubelet / 时空 patch**，或用 temporal attention、clip-level encoder 在视觉侧先压缩时间关系；另一些接口仍是稀疏抽帧后再融合。前者也不是完整观察的保证：帧率、clip 长度、时序下采样和 token 压缩仍会遗漏短事件或模糊事件边界。Agent 应以目标 API 实际处理的时间粒度，而不是“原生视频”宣传词，设计采样和 eval。

## 融合策略的直觉

| 策略 | 直觉 | 对 Agent 的影响 |
|---|---|---|
| **Early fusion** | 较早将多模态表示放入共同处理层 | 可能更早建模细粒度跨模态关联，但输入对齐与成本也更复杂 |
| **Late fusion** | 各模态先独立处理，较晚再合并结果 | 易于替换 ASR/OCR/CV 组件，但跨模态细节可能受中间摘要限制 |
| **Cross-attention** | 一个模态的 token 选择性关注另一个模态表示 | 可让文本问题聚焦相关视觉/音频信息；不保证关注位置可解释或正确 |
| **统一 token 序列** | 视觉、音频和文本 token 进入类似语言序列 | 接口简单，但 token 预算、位置和时序编码成为关键限制 |

它们描述的是信息在哪里交互，不能单独预测最终任务表现。对一个具体视频任务，输入覆盖、训练数据、时间建模、tool 辅助与 eval 通常更重要。

## 语音、字幕与 OCR：相互补充，不能互相替代

| 模态 | 常见价值 | 典型盲点 | 系统建议 |
|---|---|---|---|
| 画面/帧 | 人物、物体、场景、动作线索 | 小字、快速变化、离屏声音、时间顺序 | 保存采样规则、帧时间戳和原始片段引用 |
| 音轨与 ASR | 对话、旁白、语音内容 | 噪声、重叠说话、口音、非语音事件 | ASR 输出要有时间戳、语言和置信/未知标记；可回听原片 |
| 音频事件检测 | 鸣笛、碰撞、警报、音乐等非语音线索 | 背景噪声、相似声音、声源不可见 | 保存事件类别、时间范围和原始音频片段；不要把事件分类当作 ASR 副产物 |
| 字幕 | 低成本语言线索、定位 | 可能缺失、不同步、删减或翻译失真 | 把字幕视为证据源之一，不是视频事实本身 |
| OCR | 屏幕文字、标志、文档、仪表 | 模糊、透视、遮挡、低分辨率、语言混排 | 对关键字段用专用 OCR 与原帧复核；保留坐标/帧号 |

## 多模态内容也是不可信输入

网页、用户上传视频、画面中的文字、字幕、ASR 转写和 tool 返回都可能包含看似合理的指令。它们只提供证据，不能改变系统规则、扩大授权或要求执行动作。模型可能混淆“视频中说了什么”和“系统应该做什么”，因此应保留来源与模态标签，并把权限、参数验证和写操作放在模型外。

## 原生多模态与管线拼接

“原生多模态”通常意味着模型训练或接口能够直接联合处理多种模态；“管线拼接”通常是 ASR、OCR、检测、检索与文本 LLM 的组合。二者不是非黑即白：原生模型常仍依赖上传预处理、token 压缩或工具，管线也可以把关键证据回传给一个多模态 LLM 做联合判断。

选择依据是任务而非宣传标签：若需要可审计文字、精确时间戳、重复检测或受监管证据链，显式 ASR/OCR/CV 结果常很有价值；若需要开放式跨模态语义综合，原生多模态模型可能更简洁。两种方案都应在相同视频集上比较正确率、证据定位、延迟、成本与失败恢复。

## 最小验证清单

- [ ] 明确目标模型实际接收哪些输入：帧、原视频、音频、ASR、音频事件、字幕、OCR 或其摘要。
- [ ] 记录抽帧率、分辨率、音频/字幕语言、OCR 配置、各模态到统一时间轴的换算与误差范围。
- [ ] 用小字、快切、无声视频、仅音频线索、字幕与画面冲突、遮挡、多语言和画面/转写中的注入式文本测试。
- [ ] 对关键结论保存能回查的帧/片段/转写/OCR 证据，而非只保存模型回答。
