# 视频 Agent 的可靠性与架构

> [!important] 一句话核心
> 视频模型适合把视听证据转成语义判断，但可靠的视频 Agent 必须把“看到了什么、何时看到、证据够不够、允许做什么”从模型语言中剥离出来，交由数据管线、验证器、权限系统和人工复核共同保证。

## 先把视频任务写成契约

“分析这段监控”不是可执行任务。最小契约需要至少包含：

| 字段 | 必须明确的内容 | 示例 |
|---|---|---|
| 目标 | 输出支持什么决定 | 为人工审核生成疑似安全事件候选，不自动处罚 |
| 观察范围 | 视频哪一段、哪些模态可用 | 仅 09:00–10:00 的画面和 ASR；没有可靠 OCR |
| 事件定义 | 什么算一次事件 | 人进入限制区并持续超过 5 秒；多人同时进入按事件而非人数计 |
| 时间精度 | 允许多大误差 | 返回片段 ID 与约 3 秒范围，不承诺帧级边界 |
| 证据 | 可接受的来源 | 原始帧、时间戳、ASR/OCR 记录；不允许凭模型常识补全 |
| 输出 | 结构、状态和未知值行为 | 事件、时间范围、证据、`not_observed` / `insufficient_evidence` / `confirmed_negative`、是否需要复核 |
| 动作权限 | 模型输出能触发什么 | 仅创建人工工单；通知或删除视频须服务端授权 |

没有这些定义，模型即使“看对了”也难以验收；看不清时更会被迫猜测。

## 一个可审计架构

视频 Agent 通常应分成可替换的阶段，而不是让单次多模态调用承担全部工作：

1. **接入与规范化**：校验文件、访问权限、元数据、编码和时区；把 PTS、帧号、ASR/OCR/字幕时间换算到版本化的统一时间基准，并记录可接受误差。
2. **覆盖与索引**：保留原始视频引用；抽帧/切片并记录采样策略、帧时间和遗漏风险；可建立字幕、ASR、音频事件、OCR、镜头和对象索引。
3. **候选发现**：用检索、轻量检测、规则或多模态模型找到可能相关片段；候选不是已确认事件。
4. **局部复核**：围绕候选加密采样，读取相关音频、字幕、OCR 或检测/跟踪结果；将证据回传模型做语义综合。
5. **验证与决策**：代码校验时间范围、schema、重复、授权和业务规则；按风险阈值路由为自动低风险动作、请求补充或人工审核。
6. **审计与学习**：保存视频/片段 ID、模型与工具版本、采样配置、时间换算、证据、输出、人工结论和失败标签，供复现、回滚与 eval。

> [!tip] 模型负责“这段证据意味着什么”
> 时间换算、文件权限、重复合并、告警限流、工单写入和保留策略是确定性系统职责。即使模型可以用自然语言描述这些规则，也不应成为唯一执行者。

### 证据谱系与状态

每个事件至少应保存：`video_id`、`clip_id`、统一时间范围、帧号或 PTS、模态来源、采样策略、模型/OCR/ASR 版本、原始证据引用、输出状态和复核结果。这样才能解释结论是基于什么观察得出，并在模型、转码或采样策略变化后重放。

状态应包含原因，而不是只存一个布尔“发现”：`not_observed` 表示覆盖不足，`insufficient_evidence` 表示已观察到候选但无法确认，`confirmed_negative` 只在任务要求的覆盖已满足时使用。系统应记录状态是由缺失模态、画质、采样、冲突证据还是模型/工具故障触发。

### 人工审核与运行治理

人工审核不是一个抽象的兜底按钮。系统需要有带优先级、证据包、责任归属、时限和吞吐监控的 review queue；队列积压、证据缺失或高风险事件应触发降级、限流或停止自动动作。线上同时监控覆盖率、状态分布、证据可回查率、人工推翻率、模型/工具错误率、端到端延迟和单位视频成本。

视频与证据还需要最小化访问和保留：按任务限制可见视频范围与可导出证据，记录访问审计，定义保留/删除期限，并在需要时对人脸、车牌、语音或文本做脱敏。模型的自然语言判断不能决定这些数据治理规则。

## 工具怎样与模型协作

| 需要的能力 | 合适的机制 | 模型应做什么 | 程序应做什么 |
|---|---|---|---|
| 读取指定片段 | 受控视频/帧提取 tool | 选择需要进一步观察的时间范围 | 验证范围、返回真实片段与元数据 |
| 文字内容 | OCR / ASR tool | 判断文字或转写对任务是否相关 | 保留坐标/时间戳、语言和原始证据 |
| 精确对象计数或轨迹 | 检测/跟踪模型 + 规则聚合 | 解释计数定义中的语义例外 | 去重、轨迹匹配、算术和阈值计算 |
| 历史案例查询 | 检索系统 | 比较候选与规则/案例 | 过滤权限、返回来源与版本 |
| 创建告警/工单 | 业务 tool | 提出建议和可读摘要 | 验证策略、授权、幂等键和执行结果 |

## 失败与降级策略

| 失败信号 | 不应做什么 | 建议行为 |
|---|---|---|
| 视频损坏、时间轴未知 | 用猜测时间戳继续 | 返回输入错误，要求重新转码或元数据 |
| 帧太少/模糊/遮挡 | 断言“没有发生” | 标记 `not_observed` 或 `insufficient_evidence`，扩大采样或人工复核 |
| ASR、字幕、OCR 相互冲突 | 静默选择看似合理的一项 | 保留冲突来源和时间，按任务规则升级 |
| 模型输出了精确时间但无片段依据 | 直接写入业务系统 | 验证证据链接；无链接则降级为候选 |
| review queue 积压或证据包不完整 | 继续扩大自动判定范围 | 限流、优先处理高影响事件，并暂停需要人工确认的动作 |
| 模型、转码或工具版本回归 | 静默替换线上结果 | 以固定 eval 和线上指标检测回归，回滚版本或降级到已验证流程 |
| 高风险判定 | 让模型单独处罚、删除或报警 | 人工确认或多层政策/证据门控 |

## 视频任务的 eval 不能只看回答文本

建立带标注原片和证据时间范围的评估集，按场景、画质、时长、对象密度、语言和事件难度分层。除答案正确率外，追踪：候选召回、误报、时间定位误差和时间轴漂移、计数误差、证据可回查率、状态原因码的正确使用率、人工推翻率、review queue 等待时间、模型/工具错误率、端到端延迟和单位视频成本。

版本化的不仅是 prompt，还包括抽帧率、编码分辨率、视觉/ASR/OCR/音频事件模型、时间坐标换算、目标多模态模型、tool schema 和业务策略。任何一项改变都可能让结果回归。

## 最小检查表

- [ ] 输出中的每个事件能回链到视频/片段 ID、统一时间范围、模态来源和至少一项原始或可复核证据。
- [ ] `not_observed`、`insufficient_evidence` 和 `confirmed_negative` 是不同状态，并保存触发原因。
- [ ] 高风险动作不由模型输出直接执行。
- [ ] 计数、去重、时间换算和权限在程序层验证。
- [ ] review queue 有责任归属、时限、积压告警和降级策略。
- [ ] 视频、证据和访问记录有最小权限、保留期限和必要的脱敏策略。
- [ ] eval 包含快事件、低质量画面、音画冲突、无字幕和长视频样本。
