# 从模型认知到 Agent 设计决策

> [!important] 一句话核心
> 不要先问“Agent 要不要更自主”，而要逐项问：这一步需要概率语义判断、外部事实、精确计算、真实执行、长期状态还是人类承担责任？把每项交给最能保证它的层。

## 一张分工表

| 任务/失败根因 | 主要机制 | 模型应负责的部分 | 必要护栏 |
|---|---|---|---|
| 用户意图、模糊文本、开放摘要 | LLM | 语义理解、候选生成、软规则判断 | 任务契约、边界样例、人工抽检 |
| 私有、实时或需引用的事实 | Retrieval / 数据库 / tool | 选择查询、解释带来源结果 | 权限过滤、来源/时间、未知值 |
| 数学、计数、排序、去重 | Code / SQL / 专用算法 | 解释规则、处理语义例外 | 单元测试、输入校验、可重放计算 |
| JSON、枚举、字段类型 | API schema + parser | 字段语义和缺失理由 | 原生结构化输出、解析、业务校验 |
| 外部写入/不可逆动作 | Tool + policy | 提出动作、填候选参数 | 服务器端授权、幂等、真实状态回读 |
| 多步任务进度 | 持久化 state + workflow | 决定下一步或总结可丢弃内容 | 任务 ID、检查点、停止条件、恢复策略 |
| 视频事件/时间定位 | 采样、ASR、音频事件、OCR/CV + 多模态 LLM | 综合多模态证据、判断语义 | 统一时间轴、证据谱系、状态原因码、人工复核 |
| 高影响与低证据决策 | Human-in-the-loop | 提供证据摘要与候选建议 | 审核队列、责任归属、审计记录 |

## 选择复杂度的阶梯

1. **先做单次、可评估的 LLM 调用**：明确输入、证据、输出和失败；不要一开始搭多 Agent。
2. **补足缺失能力**：事实用 retrieval，实时数据/动作用 tool，结构用 schema，确定性规则用 code，跨轮进度用 state。
3. **必要时使用固定工作流**：任务可预测地分为步骤时，采用 routing、chaining、并行或验证节点。
4. **最后才用开放 Agent loop**：仅当路径无法预设、环境能提供真实反馈、风险可控且有停止/人工接管机制时采用。

这与 [[building-effective-agents|Building Effective Agents]] 的“先简单后复杂”原则一致。多一步模型调用不仅增加成本和延迟，也会增加上下文漂移、错误累积和调试难度。

## 文本与视频的同一诊断法

当结果错了，先区分失败层，而不要立即重写 prompt：

| 观察 | 优先检查 | 示例 |
|---|---|---|
| 缺少事实 | 证据是否存在且被检索 | 文本回答编造政策；视频漏掉未采样时刻 |
| 事实在输入中却被忽略 | context 组织、位置、噪声、任务定义 | 长合同中漏掉中段条款；长视频中未回看候选片段 |
| 数据试图改变规则或触发动作 | 消息边界、tool 权限与参数来源 | 网页或 OCR 文字要求忽略规则；tool 返回伪装成授权 |
| 格式/计算/计数错 | schema、code、专用工具 | JSON 漏字段；视频人数被重复计数 |
| 声称已执行 | tool 授权与真实反馈 | 模型说已退款；模型说已创建告警 |
| 复杂步骤丢失进度 | state、workflow、停止条件 | 重复检索；反复处理同一视频片段 |
| 能力/成本不匹配 | 模型和架构选择 | 小模型做长时序推理；强模型用于简单正则提取 |
| 无法判断改动好坏 | eval 设计 | 只用一个 demo 评估采样/模型升级 |

## 最小可靠性闭环

任务契约 → 最小 baseline → 代表性输入 → 观察失败层 → 只改变一个主要变量 → 同条件 eval → 版本化发布或回滚。

评估记录应包含：输入和真值/评分标准、模型和快照、prompt、context 构造、采样参数、tools/schema、原始输出、验证结果、延迟、token/视频处理成本和人工判定。视频任务还应保存统一时间轴、采样覆盖、证据引用和状态原因码。这样才可以归因于一次改动。

## 决策前的问题清单

- [ ] 这个输出将驱动什么下游动作，错误的最高影响是什么？
- [ ] 模型此时需要的事实来自哪里，缺失或冲突时返回什么？
- [ ] 哪些字段或动作必须由 code/policy 保证，哪些是模型才适合做的语义判断？
- [ ] 当前 context 是否只含必要、带来源、权限正确的材料？
- [ ] 是否需要持久化真实 state，而非保留一段模型摘要？
- [ ] 视频任务是否记录了抽样覆盖、统一时间轴、状态原因和能回查的片段证据？
- [ ] 是否已有足够的 eval、线上指标、人审容量和回滚条件来支持这项改动？
