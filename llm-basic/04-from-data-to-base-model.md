# 从数据到基础模型

> [!abstract] 本文回答什么
> 一个未经对话和指令对齐的 Base Model 是怎样从原始数据产生的？数据、tokenizer、预训练目标、梯度更新、模型容量与计算预算分别做了什么？

## 完整生产流程

```mermaid
flowchart LR
    A["原始语料与代码等数据"] --> B["许可、隐私与安全治理"]
    B --> C["解析、清洗与语言识别"]
    C --> D["去重、质量过滤与污染控制"]
    D --> E["数据分类、配比与采样"]
    E --> F["训练 Tokenizer"]
    F --> G["构造 Token 序列"]
    G --> H["初始化模型参数"]
    H --> I["下一 Token 预训练"]
    I --> J["Checkpoint 与基础评测"]
    J --> K["Base Model"]
```

这不是一次线性、无反馈的流水线。训练团队会根据 loss、数据统计、评测、异常行为和基础设施状态反复调整数据配比、学习率或训练阶段。对 Agent 开发者，关键是理解每个节点怎样塑造最终模型。

## 1. 原始数据不是直接喂给模型

预训练数据可能包含自然语言、代码、数学、结构化数据及其他可序列化内容。进入训练前至少涉及：

- **来源与许可**：是否有权收集、训练、保留和发布相关能力。
- **隐私处理**：识别和减少个人信息、凭据及敏感数据。
- **解析与规范化**：从网页、文档或代码仓库中抽取正文和结构。
- **去重**：减少完全相同或高度相似的内容反复影响训练。
- **质量过滤**：去除乱码、模板页、垃圾文本、低信息密度或恶意内容。
- **分类与标注元数据**：语言、领域、来源、质量、安全类别和时间。
- **评测污染控制**：减少基准答案直接出现在训练数据中造成的虚高。

> [!important] 数据管线本身就是模型设计
> 模型不会“接触互联网后自动获得客观世界知识”。它学习的是被选择、过滤、重复和加权后的训练分布。数据缺失、冲突、过时与偏差会进入参数。

## 2. 数据配比决定训练信号出现的频率

假设数据分为 $K$ 类，类别 $k$ 的采样权重为 $alpha_k$：

$$
p_{train}(x)=\sum_{k=1}^{K}alpha_k p_k(x), \qquad \sum_{k=1}^{K}alpha_k=1
$$

公式说明：训练分布不是简单把所有文件等概率拼在一起；各类数据的权重决定模型更新时看到不同模式的频率。提高代码、数学或某种语言的权重，可能增强相关能力，也可能挤占其他数据的计算预算。

数据量不等于有效信号量。大量近重复、低质量或单一模板会让训练计算被重复模式占用。

## 3. Tokenizer 与词表也是训练产物

Tokenizer 通常在代表性数据样本上学习词表。它决定：

- 哪些字符串被视作常见整体；
- 不同语言、代码和数字需要多少 token；
- 模型输入输出的基本离散单元；
- embedding 与输出投影的词表维度 $V$。

Tokenizer 不是纯粹的前处理细节。切分效率影响训练中每单位计算覆盖多少内容，也影响 Agent 使用时的 context 成本。详见 [[01-token-embedding-and-transformer#1. Tokenizer：把字符串变成离散 ID|Tokenizer 基础]]。

## 4. 训练样本：把连续 Token 流切成序列

清洗后的文档被编码为 token，并按长度打包为训练序列。需要处理文档边界、结束 token、padding 或 packing。

不当拼接可能让模型学习到虚假的跨文档关系；过度切断又会丢失长程结构。训练最大长度还会影响模型对长 context 的熟悉程度，但不是最终可用长度的唯一因素。

## 5. 初始化模型参数

训练开始时，embedding、attention、FFN 等参数通常是满足特定尺度分布的随机值。此时模型的输出接近无意义概率分布。

参数量来自各矩阵维度与层数。参数更多意味着模型拥有更大的函数容量，但也带来更高训练和推理资源需求。参数量本身不保证：

- 数据质量；
- 后训练质量；
- 事实可靠性；
- 长 context 利用率；
- 对特定 Agent 工具的适配。

## 6. 预训练目标：提高真实下一个 Token 的概率

对 token 序列 $(t_1,\ldots,t_T)$，自回归模型最小化负对数似然：

$$
\mathcal{L}(\theta)=-\frac{1}{T}\sum_{i=1}^{T}\log p_\theta(t_i\mid t_{<i})
$$

准确解释：

- 模型读取位置 $i$ 之前的 token。
- 它给整个词表分配概率。
- 如果数据中的真实 token 概率低，loss 较大。
- 训练调整参数 $\theta$，让真实序列在模型下更可能。

这个目标没有直接要求“回答问题”“服从用户”“只说真话”或“正确调用工具”。那些行为需要数据分布、后训练和运行时系统共同形成。

## 7. 梯度下降怎样把统计规律写入参数

反向传播计算 loss 对参数的梯度，再由优化器更新：

$$
\theta_{s+1}=\theta_s-\eta_s\widehat{g}_s
$$

- $s$ 是训练 step。
- $\eta_s$ 是该 step 的学习率。
- $\widehat{g}_s$ 是根据当前 mini-batch 估计的梯度，实际优化器还会维护动量和尺度等状态。

公式说明：训练不是把文档逐条存进数据库，而是让大量样本共同改变共享参数。某个事实可能被许多上下文重复强化，也可能与冲突版本共同影响参数。因此参数知识是分布式统计表示，不具有数据库式来源、版本和可删除记录。

## 8. Batch、Step、Epoch 与 Token Budget

- **Batch**：一次用于估计梯度的一组 token。
- **Step**：进行一次参数更新。
- **Epoch**：完整遍历一次给定数据集；大规模混合数据未必严格按 epoch 组织。
- **Token budget**：整个训练实际处理的 token 总数。

训练计算可粗略理解为同时受参数量 $N$ 与训练 token 数 $D$ 控制：

$$
C \propto N D
$$

常数取决于架构和实现。公式强调：更大模型需要足够数据和计算才能有效训练；只增加参数但不给足训练 token，或反之，都可能不是最佳资源配置。

## 9. Scaling Law 说明什么

经验 scaling law 常把验证 loss 写成模型规模、数据和计算的幂律下降加不可约项：

$$
L(N,D)\approx L_\infty+aN^{-alpha}+bD^{-\beta}
$$

它表达的是统计趋势：在合适的数据和优化下，增加容量与数据通常能可预测地降低平均 loss。它不表示：

- 每项具体能力都平滑提升；
- 数据内容不再重要；
- 更低平均 loss 自动带来安全、诚实或工具可靠性；
- 单个 benchmark 或真实任务一定同比提升。

## 10. Perplexity：预测分布的平均不确定度

若平均交叉熵为 $L$，perplexity 为：

$$
\operatorname{PPL}=e^L
$$

较低 PPL 表示模型对该数据分布的真实 token 平均赋予更高概率。不同 tokenizer、数据集和预处理下的 PPL 不能直接横向比较；PPL 也不是 Agent 任务成功率。

## 11. Checkpoint 与训练监控

训练会周期性保存 checkpoint，包括模型参数和必要的优化状态。团队监控：

- 训练与验证 loss；
- 梯度、激活和数值稳定性；
- 数据吞吐与硬件故障；
- 基础语言、知识、推理和代码评测；
- 记忆、污染、安全和偏差风险；
- 不同数据领域的能力变化。

异常 checkpoint 可以回退，但训练指标正常不代表模型已经适合作为助手。

## 12. 必要的训练基础设施背景

大模型参数、激活和优化器状态通常无法放在单个加速器上，因此训练会拆分：

- 数据在不同设备上并行处理；
- 矩阵或层跨设备切分；
- 激活在前向阶段后重新计算以换取显存；
- 使用较低精度计算并保留必要的数值稳定性；
- checkpoint、故障恢复和通信成为训练系统的一部分。

这些技术决定模型是否能在可接受成本下训练，但本身不定义语言目标或对齐目标。本文只需建立这一背景。

## 13. Base Model 获得了什么

完成预训练的 Base Model 通常获得：

- 语言与代码的统计结构；
- 大量训练分布中的世界模式；
- 根据 context 续写、归纳和转换文本的能力；
- 一定程度的 in-context learning；
- 随规模、数据和训练出现的组合与推理能力。

它的接口仍是“给前缀生成可能的后续”。如果提示像问答，它可能回答；如果提示像网页，它也可能续写网页；它不天然知道哪个角色是用户，也不天然遵循安全或工具协议。

> [!warning] Base Model 不是较差的聊天模型
> 它优化的行为目标不同。Assistant Model 不是简单在 Base Model 外加一个系统提示，而是通过后训练改变输出分布。

## 14. Base Model 没有获得什么

- 可追溯、实时、无冲突的事实数据库；
- 对用户指令的稳定优先级；
- 对权限、法律或业务规则的确定性遵守；
- 自动访问工具和外部状态的能力；
- 经过校准的置信度；
- 自带长期记忆和 Agent loop。

从 Base Model 到 Assistant Model 的变化见 [[05-from-base-model-to-assistant-model|下一篇]]。

## 对 Agent 开发的含义

1. 参数知识继承训练数据的时间、覆盖、重复和冲突，事实任务必须有外部来源。
2. tokenizer 和数据分布会导致语言、代码、格式上的能力与成本差异。
3. 能续写某种工具调用格式，不代表模型获得了工具权限或真实执行能力。
4. 模型升级相当于替换一个由数据、训练和后训练共同定义的概率依赖，必须重新 eval。
5. 不应通过自然语言追问模型“你是否在训练中见过这条数据”来获得可靠来源证明。
