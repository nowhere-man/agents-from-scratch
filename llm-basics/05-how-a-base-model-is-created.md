# 基础模型怎样产生

> [!abstract] 本章只回答一个问题
> 一个参数近似随机的 Transformer，怎样通过不断预测训练文本的下一个 Token，逐渐变成能够续写语言的基础模型？

## 前置知识

[[04-modern-llm-architecture|上一章]]已经解释：一串 Token 会经过 Embedding、多个 Decoder Block 和 LM Head，最终得到下一个 Token 的概率。本章不再展开 Transformer 内部结构，而是追踪这些计算中的数值怎样被训练出来。

第 02 章已经完成数据准备。这里从一个已经 Tokenize 的训练序列开始：

> 北京今天下雨，出门要带伞。

## 1. 训练真正要改变什么

模型的层数、Attention 和 FFN 等结构在训练前就已经确定，但其中大量矩阵还没有合适的数值。例如：

- Embedding Table 决定每个 Token ID 最初查到什么向量；
- Attention 投影矩阵决定每个位置怎样读取上下文；
- FFN 矩阵决定怎样变换已经收集到的特征；
- LM Head 决定最后的 Hidden State 怎样映射成词表分数。

这些可被训练调整的数值统称 **参数**。矩阵中的参数常被叫作 **权重**，因此“模型权重”也常泛指模型保存的全部参数。

训练前，参数通常按经过设计的数值范围近似随机初始化。模型虽然已经具备完整计算结构，但还不知道“下雨”后常出现什么，也不知道“出门要带”后应该提高“伞”的概率。

训练要做的不是把句子存入某个表，而是反复完成下面的闭环：

~~~mermaid
flowchart LR
    A[取一批训练 Token] --> B[前向计算预测]
    B --> C[用真实 Token 计算 Loss]
    C --> D[反向传播计算梯度]
    D --> E[优化器更新参数]
    E --> F[取下一批训练 Token]
    F --> B
~~~

下面先把其中一次循环走完整。

## 2. 前向计算：当前模型先做一次预测

训练序列不只构造一个问题。对每个位置，左侧 Token 是输入，右侧紧邻 Token 是预测目标：

| 模型看到的前缀 | 应提高概率的下一个 Token |
|---|---|
| 北京 | 今天 |
| 北京今天 | 下雨 |
| 北京今天下雨，出门要带 | 伞 |

借助 Causal Mask，这些位置可以在一次前向计算中并行训练，同时每个位置仍只能读取自己的左侧。

假设当前模型处理“北京今天下雨，出门要带”后，对几个候选给出：

| 候选 Token | 当前概率 |
|---|---:|
| 伞 | 0.02 |
| 水 | 0.06 |
| 门 | 0.04 |
| 其他 Token 合计 | 0.88 |

训练数据告诉模型真实下一个 Token 是“伞”。前向计算期间，每层还会产生各位置的 Hidden State、Attention 输出和 FFN 输出。这些随当前输入临时产生的中间数值叫作 **激活值**。

> [!note] 参数和激活值不是一回事
> 参数是模型长期保存、训练时会更新的数值；激活值是“这批输入经过当前参数后算出的中间结果”。换一批输入，激活值会变化。训练时要保留必要的激活值，因为反向传播要用它们追溯每个参数的影响。

## 3. Loss：把“预测得有多差”变成数值

模型给整个词表都分配了概率，但训练需要一个可以优化的数值。对一个位置，常见 Loss 是：

$$
\mathcal{L}=-\log p(t_{correct}\mid context)
$$

在当前例子中：

- $context$ 是“北京今天下雨，出门要带”；
- $t_{correct}$ 是真实 Token“伞”；
- $p(t_{correct}\mid context)$ 是模型当前给“伞”的概率；
- 概率只有 0.02 时 Loss 较大，概率接近 1 时 Loss 较小。

一个训练 Batch 有许多目标位置，实际 Loss 通常是这些位置损失的汇总。它把大量“每个位置预测得怎么样”压成一个训练信号。

Loss 只告诉我们整体错了多少，还没有回答：数十亿个参数中，哪个应该增大，哪个应该减小。

## 4. 反向传播：把 Loss 追溯到每个参数

前向计算是一条连续因果链：某个权重影响某层激活值，激活值影响后续层，最后影响“伞”的 Logit、概率和 Loss。

**反向传播**就是沿这条已经发生过的计算链从 Loss 往回追，利用链式法则求出每个参数对本次 Loss 的局部影响。这个影响叫作 **梯度**：

$$
\nabla_{\theta}\mathcal{L}
$$

- $\theta$ 代表模型的全部可训练参数；
- $\mathcal{L}$ 是本批数据的 Loss；
- 梯度中的每个数对应一个参数，表示该参数轻微增大时，Loss 会向哪个方向、以多快速度变化。

通俗地说：==反向传播不负责直接“学会答案”，而是根据这次预测错误，为每个可调数值算出一条应往哪边调整的建议。==

这些建议不是“把表示雨的参数调大”之类的人类规则。一个预测经过许多层和参数，梯度会把影响分配回整条计算路径；同一个参数也会同时受到 Batch 中许多 Token 的共同影响。

## 5. 优化器：真正更新参数

得到梯度后，优化器才修改参数。最简形式是：

$$
\theta_{new}=\theta_{old}-\eta\nabla_{\theta}\mathcal{L}
$$

- $\theta_{old}$ 是更新前的参数；
- 梯度指向 Loss 上升较快的方向，所以前面使用减号；
- $\eta$ 是 **学习率**，控制这一步走多远；
- $\theta_{new}$ 会用于下一次前向计算。

实际训练常使用 AdamW 等优化器，它还会综合近期梯度的方向和尺度，但核心闭环不变：根据梯度调整参数，使类似训练输入上的正确 Token 以后更可能出现。

一次参数更新称为一个 **Step**。一个 Step 不会把“伞”的概率直接变成 100%，因为更新还要兼顾 Batch 中的其他位置，也要避免对单个样本改得过猛。经过许多相关语境后，模型才逐渐形成可复用的天气关系、中文语法和常见搭配。

这些规律共享同一组参数，而不是每条知识各占一个固定地址。

## 6. 一次更新怎样扩大成预训练

现实训练不会每次只处理一句话：

- **Batch**：一次并行参与前向和反向计算的一批训练 Token；
- **Step**：用一个 Batch 计算梯度并更新一次参数；
- **训练 Token 数**：整个训练过程中实际处理过多少 Token；
- **Epoch**：完整遍历一次指定数据集。

大规模预训练的数据会混合、重采样和分阶段调整，因此常用训练 Token 总数描述进度，不一定严格按 Epoch 组织。

训练者还会预先选择学习率、Batch 大小、层数和训练步数等配置。这些叫作 **超参数**：它们控制模型结构或训练过程，但不是模型从文本中学出的参数。

每个 Step 都重复同一因果链：

~~~text
当前参数
→ 对一批真实文本做预测
→ Loss 衡量预测差距
→ 反向传播得到梯度
→ 优化器更新参数
→ 下一批文本上的预测略有变化
~~~

模型接触大量语言、代码和结构化序列后，反复出现且有助于预测的统计规律会逐渐编码进共享参数。

## 7. 三个容易混淆的“量”

| 概念 | 指什么 | 生命周期 |
|---|---|---|
| 总参数量 | 模型一共保存多少可训练数值 | 随 Checkpoint 长期保存 |
| 激活值 | 某批输入经过各层时产生的中间结果 | 随输入临时产生 |
| 每 Token 激活参数量 | 处理一个 Token 时实际参与主要计算的参数规模 | 描述一次计算使用哪些参数 |

Dense 模型通常让每个 Token 经过相同的主要参数。第 04 章介绍的 MoE 虽然保存多个 Expert，却只为每个 Token 选择少数 Expert，因此总参数量可以远大于每 Token 实际使用的参数量。

“激活参数”这个简称容易被误解为激活值，最好明确说“每 Token 激活参数量”。

## 8. Checkpoint 保存的是哪个时刻的模型

预训练需要很长时间，系统会周期性保存 **Checkpoint**。它至少包含当时的模型参数；为了恢复训练，通常还会保存优化器状态、训练步数和相关配置。

Checkpoint 的意义是“训练走到这一刻时，整个数值系统处于什么状态”，不是从模型中单独导出的一段知识。加载较早 Checkpoint，就等于回到较早的一整套参数。

用于推理时，通常需要模型结构配置、Tokenizer 和训练完成的权重，不再需要反向传播使用的激活值，也不一定需要优化器状态。

## 9. Scaling Law

走完整个训练闭环后，可以看到最终效果至少受三类资源共同限制：

1. **参数量 $N$**：模型有多大容量表示规律；
2. **训练数据量 $D$**：模型获得多少不同训练信号；
3. **计算预算 $C$**：能执行多少前向、反向和更新计算。

Scaling Law 是实验中观察到的经验趋势：在数据质量和训练方法等条件相近时，合理增加参数、数据和计算，验证 Loss 往往以较平滑、可预测的方式下降。

可以抽象写成：

$$
L=f(N,D,C)
$$

这里不是让你代数求解，而是在强调三个量必须配合：

- 只有更大模型，却没有足够训练 Token 和计算，许多参数得不到充分训练；
- 只有更多数据，却没有足够容量或计算，模型也难以吸收其中规律；
- 一味重复低质量数据，不能等价替代新的有效训练信号。

> [!important] Scaling Law 预测的是总体趋势
> 它不能保证某个具体问题答对，不能保证事实可靠、安全或服从指令，也不等于“参数翻倍，智能翻倍”。

有些能力在离散评测上看似突然出现，可能是底层能力平滑提升后刚好越过“答对”的评分阈值，也可能是多个子能力必须同时达到一定水平。不能只凭一个跳变分数断言模型内部突然新增了独立模块。

## 10. 训练完成后，权重里有什么

完成预训练的权重编码了对训练分布有助于预测的统计规律，包括语言结构、概念关系、常见事实模式、代码模式和任务格式。

它不是数据库：

- 没有为每条事实保留稳定记录 ID；
- 不一定能追溯某句话来自哪份文档；
- 冲突和过时内容可能共同影响参数；
- 一个规律通常由许多参数共同表示，一个参数也参与许多规律。

最终得到的 **Base Model** 已经能够续写文本、生成代码，并表现出知识与一定推理能力。但它的核心接口仍然是“给定前缀，预测后续”。面对“请解释彩虹为什么出现”，它可能直接回答，也可能续写成网页、试题或另一段对话。

下一章要解决的新问题因此自然出现：怎样继续训练这套已经有能力的权重，让“理解用户指令并作为助手回应”成为更稳定的行为？
