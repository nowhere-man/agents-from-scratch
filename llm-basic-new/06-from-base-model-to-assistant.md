# 基础模型怎样成为助手模型

> [!abstract] 本章只回答一个问题
> 已经会续写文本的基础模型，怎样变成会回答问题、遵循指令并使用工具协议的助手模型？

## 前置知识

[[05-how-a-base-model-is-created|上一章]]解释了预训练怎样调整权重。后训练也会调整权重，但使用的数据和目标更聚焦于人类期望的交互行为。

## Base Model 为什么不好直接聊天

输入“请用一句话解释彩虹为什么出现”，基础模型可能回答，也可能继续补写成另一条要求。预训练数据包含书籍、网页、代码和对话等多种模式，“用户发出指令，助手回答”只是其中一种。

要让助手行为稳定出现，需要后训练提高它的概率。

~~~mermaid
flowchart LR
    A[基础模型] --> B[指令微调 SFT]
    B --> C[偏好与奖励学习]
    C --> D[安全和专项行为训练]
    D --> E[评测与发布]
    E --> F[助手模型]
~~~

## SFT：用示范告诉模型怎样回答

Supervised Fine-Tuning 使用高质量的输入—理想输出示例继续训练。训练目标仍是预测下一个 Token，只是数据变成了精心组织的指令和回答。

它让模型学习角色边界、回答模式、常见任务格式、语气和适当的拒绝方式。SFT 不是把自然语言规则编译成硬代码，而是提高与示范相似的行为概率。

## 为什么只靠示范还不够

很多问题存在多个合理回答。示范只说明“这个答案可以”，却不直接说明两个回答中哪个更清楚、真实或安全。因此可以让人或评估器比较多个候选，形成 chosen / rejected 或评分数据。

## 偏好优化：让更好的回答更可能出现

### Reward Model 与 RLHF

先训练 Reward Model 学习给回答打分，再通过强化学习提高高奖励回答的概率。

### 直接偏好优化

DPO 等方法直接利用“回答 A 优于回答 B”的数据，拉高 chosen 的相对概率，降低 rejected 的相对概率。

方法细节不同，但共同目的都是改变模型在多个可能回答之间的行为倾向，而不是安装新的 Transformer 模块。

## 可验证奖励

数学答案、代码测试、结构约束等任务可以由程序检查。模型生成多个尝试后，可根据结果获得训练信号。

这种反馈更明确，但验证器可能只检查结果、漏掉脆弱过程，模型也可能找到奖励规则的漏洞。很多开放问题本身也没有唯一可验证答案。

## 结果监督和过程监督

- 结果监督只评价最终答案；
- 过程监督评价中间步骤或关键决策。

过程监督能提供更密集的反馈，但高质量标注更昂贵。模型写出的可读过程也不等于神经网络内部计算的完整转录。

## 安全训练改变什么

安全数据会训练模型识别风险请求、遵循策略、提供替代方案或拒绝。它能改善平均行为，却不是无法绕过的权限系统。

原因在于，指令可能冲突，攻击形式可能超出训练分布，自然语言规则也可能有歧义。后训练提供行为层防线，不替代应用外部的鉴权和执行隔离。

## Tool Calling 是怎样学会的

训练示例教模型在适当时生成约定格式，例如工具名称和 JSON 参数。模型学会选择工具、填参数和读取结果，但真正执行工具的是模型外部程序。

## Structured Output 改变什么

结构化输出训练或受约束解码能提高 JSON Schema 等格式的可靠性。即使 JSON 完全有效，字段值仍可能是错误事实。格式正确与语义正确是两件事。

## 助手模型最终改变了什么

它更倾向于遵循角色和指令、直接回答、按格式输出、在风险情况下采取训练过的行为，以及使用 Tool Call 协议。

它仍可能生成错误事实、误解指令、选错工具、漏掉长上下文信息，或表现出不可靠的自信。

> [!important] 能力、倾向和保证
> 训练赋予能力并改变行为倾向。真正的强制保证通常需要模型外部的代码、数据源、权限系统和验证器。
