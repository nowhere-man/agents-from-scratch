# 多模态视频理解模型原理

> [!abstract] 本章只回答一个问题
> 视频中的像素、声音和时间变化，怎样变成语言模型可以共同处理的表示？

## 前置知识

你已经知道文本通过 Tokenizer 变成 Token 和向量。视频模型仍使用相似主干，但必须先把图像、声音和时间压缩成可计算表示。

## 视频不是很多图片直接塞进 LLM

一段 10 分钟、每秒 30 帧的视频有 18,000 帧。若每帧再切成大量视觉 Token，数量会远超普通上下文预算。

因此视频理解的第一原则是：==在进入主模型前，系统已经进行了采样、编码和压缩。模型只能根据留下来的信息回答。==

~~~mermaid
flowchart LR
    A[原始视频] --> B[解码与采样]
    B --> C[图像帧编码]
    B --> D[音频编码或 ASR]
    C --> E[视觉 Token 压缩]
    D --> F[音频与文本 Token]
    E --> G[时间与跨模态融合]
    F --> G
    G --> H[语言模型或多模态主干]
    H --> I[回答 摘要 定位]
~~~

## 第一步：采样决定模型看到了什么

最简单的方法是每隔固定时间取一帧。它成本低，但可能漏掉发生在两次采样之间的短事件。

更复杂的采样会考虑镜头切换、运动强度、关键帧、用户问题或分层时间尺度。

| 采样方式 | 优点 | 风险 |
|---|---|---|
| 固定间隔 | 简单、覆盖全局 | 漏掉短事件 |
| 关键帧 | 减少重复画面 | 关键帧不一定包含关键动作 |
| 镜头感知 | 保留场景变化 | 镜头内部细节仍可能丢失 |
| 问题引导 | 聚焦相关片段 | 初始检索错误会限制后续回答 |

如果目标事件从未进入采样帧，后面再强的语言推理也无法恢复真实证据。

## 第二步：图像变成视觉 Token

一帧图像可以被切成 Patch，再由视觉编码器转换成向量。假设图像高 $H$、宽 $W$，Patch 边长 $P$，最简单情况下 Patch 数约为：

$$
N=(H\times W)/P^2
$$

它意味着：Patch 越小，保留的局部细节越多，但视觉 Token 越多；Patch 越大，成本越低，但小字和小物体更容易丢失。

实际系统还可能使用动态分辨率、卷积层、层级视觉编码器和 Token 合并。

## 第三步：视觉表示接入语言空间

视觉编码器产生的向量和文本 Embedding 不在天然相同的表示空间。系统需要 Projector、Cross-Attention 或 Query/Resampler 模块进行连接。

- **Projector**：把视觉向量映射到语言模型隐藏维度；
- **Cross-Attention**：文本表示按需读取视觉表示；
- **Resampler**：把大量视觉 Token 压缩成固定或较少的摘要 Token。

这些操作不是把图片翻译成一句完整文字后再交给 LLM，而是在数值表示层进行对齐和信息选择。

## 第四步：时间信息不能丢

单张图片只能说明某一刻有什么。视频理解还需知道顺序、持续时间和变化：

~~~text
人站在杯子旁
→ 人拿起杯子
→ 人把水倒入杯子
~~~

如果只看打乱后的三帧，模型可能知道出现了人、杯子和水，却不能可靠判断动作顺序。

时间可通过帧位置编码、时间戳 Token、时空 Attention、局部时间模块或分层片段表示进入模型。核心目标都是让表示包含“何时发生”和“先后如何”。

## 动作和状态变化

很多问题不是识别物体，而是识别变化：门从关闭到打开、球从手中飞出、人物进入画面。

动作可能持续很短，也可能跨越很长时间。只做单帧物体识别无法完整回答，需要比较多个时刻，并保留足够时间分辨率。

## 音频、ASR、OCR 和画面是互补证据

视频信息可能来自：

- 画面中的物体、动作和场景；
- 对话和旁白的语音转写；
- 音乐、警报、掌声等非语音声音；
- 字幕、标题、路牌和屏幕文字；
- 元数据和时间戳。

ASR 只能表示说了什么，不包含所有非语音事件；OCR 能读取文字，但可能丢失文字所在位置和出现时间；画面也不能自动说明未出现在画面中的声音来源。

可靠系统应保留证据模态和时间来源，而不是过早把所有内容压成一段无出处摘要。

## 长视频为什么需要分层

长视频无法始终以最高分辨率全部送入模型。常见思路是：

1. 把视频切成短片段；
2. 对每个片段抽取表示或摘要；
3. 建立片段级索引；
4. 根据问题检索候选片段；
5. 对候选片段使用更密集采样；
6. 汇总并保留时间证据。

这类似先看目录和章节摘要，再回到相关页面细读。第一次粗摘要一旦漏掉信息，后续检索也可能找不到，因此需要允许回看原始片段。

## 训练怎样建立多模态能力

视频模型可能组合多种训练目标：

- 图像或视频与文本的对齐；
- 根据视觉内容生成描述；
- 视频问答；
- 时间顺序和事件定位；
- 音视频同步；
- 指令和偏好后训练。

这些目标让视觉、音频和文本表示在共同任务中协作。它们不会让模型无损保存视频，每一步仍受采样和压缩限制。

## 不同任务依赖不同能力

| 任务 | 核心能力 | 常见失败 |
|---|---|---|
| 视频摘要 | 全局覆盖和事件取舍 | 过度概括、漏短事件 |
| 视频问答 | 问题引导检索与证据组合 | 找错片段后合理猜测 |
| 高光识别 | 事件重要性和领域标准 | 把视觉显著当业务重要 |
| 时间定位 | 细时间分辨率和边界判断 | 时间戳漂移 |
| 行为识别 | 物体、动作和顺序 | 静态画面混淆动作 |
| OCR/字幕理解 | 分辨率、文字识别和时间关联 | 小字、闪现文字遗漏 |

## 视频模型的能力边界

### 采样遗漏

没有被采样的瞬间通常不可恢复。

### 空间细节丢失

缩放和 Patch 压缩会损失小物体、细微表情和屏幕文字。

### 时间关系错误

模型可能识别所有事件，却弄错先后、持续时间或因果关系。

### 跨模态冲突

字幕、旁白和画面可能不一致。模型需要判断哪个来源对应问题，不能默认文字一定正确。

### 合理描述不等于有证据

模型可能根据常见场景补全没有真正观察到的细节。应要求时间戳、关键帧或片段 ID，并允许回看原始视频。

## 一个可审计的视频理解流程

~~~text
保留原始视频
→ 记录采样策略
→ 为帧、音频和 OCR 保留时间戳
→ 检索候选片段
→ 模型生成带证据引用的答案
→ 程序检查时间范围和引用存在性
→ 高风险结果人工回看
~~~

最终自然语言是结论，时间片段和原始媒体才是证据。

## 常见误解

> [!warning] 视频越长，模型看到的信息越多
> 在固定 Token 预算下，视频越长通常意味着采样更稀或压缩更强，细节反而更容易丢失。

> [!warning] 视频模型看过每一帧
> 很多系统只处理采样帧或压缩表示。必须查看具体输入管线。

> [!warning] 有时间戳就证明定位准确
> 时间戳可能来自粗粒度片段或模型估计，仍需与原始视频核对。
