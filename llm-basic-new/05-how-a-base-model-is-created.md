# 基础模型怎样产生

> [!abstract] 本章只回答一个问题
> 一个参数近似随机的 Transformer，怎样通过预训练变成能够生成语言的基础模型？

## 前置知识

你已经知道文本会变成向量，并经过 Transformer 产生下一个 Token 的概率。现在讨论这些计算中的数值怎样通过训练形成。

## 先建立完整过程

~~~mermaid
flowchart LR
    A[准备训练数据] --> B[初始化参数]
    B --> C[前向计算]
    C --> D[计算预测误差]
    D --> E[反向传播得到梯度]
    E --> F[更新参数]
    F --> G{训练是否结束}
    G -->|否| C
    G -->|是| H[基础模型]
~~~

模型结构决定“可以怎样计算”；训练决定“计算中使用哪些具体数值”。

## 参数和权重是什么

Embedding 表、Q/K/V 投影、FFN 矩阵、归一化缩放等，都包含可以通过训练调整的数值，这些数值统称 **参数**。

“权重”通常指矩阵中的可训练数值。有时人们也用“模型权重”泛指全部参数。偏置也是参数，但不一定被叫作权重。

参数不是一条条知识，也不是代码规则。一个事实或能力通常由许多参数共同参与表示，一个参数也会影响许多输入。

## 初始化：刚开始时模型什么都不会

训练开始前，参数按特定统计范围初始化，整体接近随机。结构虽然已经具备 Attention 和 FFN，输出却没有语言规律。

可以把它想成：机器内部已经装好了大量可调旋钮和连接，但还没有根据数据把它们调到有用位置。训练就是反复根据预测误差微调这些数值。

## 一次训练 Step 发生什么

继续使用样本：

> 北京今天下雨，出门要带伞。

### 1. 前向计算

模型读取前面的 Token，并给正确下一个 Token 分配概率。假设在“出门要带”后，它给“伞”的概率只有 2%。

### 2. 计算 Loss

Loss 是对预测有多差的数值总结。正确 Token 的概率越低，Loss 越高。常见的单位置损失可写为：

$$
\mathcal{L}=-\log p(t_{correct}\mid context)
$$

它不要求你计算。它只表达：正确答案概率高，惩罚小；正确答案概率低，惩罚大。Loss 给训练提供连续的“错了多少”信号。

### 3. 反向传播

模型需要知道每个参数向哪个方向改变，能让 Loss 降低。反向传播从 Loss 沿计算过程向后计算每个参数的梯度。

==梯度可以理解成给每个可调数值的局部建议：轻微增大或减小它，会怎样影响本次误差。==

### 4. 更新参数

最简更新形式是：

$$
\theta_{new}=\theta_{old}-\eta\nabla_\theta\mathcal{L}
$$

这只是在说：

- $\theta$ 代表全部参数；
- 梯度指出 Loss 增长的方向；
- 朝相反方向走一小步，通常能降低 Loss；
- $\eta$ 是学习率，控制这一步有多大。

一次更新不会让模型突然学会“雨天带伞”。大量不同样本的微小更新共同塑造出语言和知识规律。

## 参数、超参数、激活值和激活函数

| 概念 | 是否由训练学得 | 何时存在 | 例子 |
|---|---|---|---|
| 参数/权重 | 是 | 保存在模型中 | Q/K/V 矩阵、Embedding 表 |
| 超参数 | 否，由训练方案设定 | 控制训练或结构 | 学习率、层数、Batch 大小 |
| 激活值 | 否，是计算结果 | 处理当前输入时临时产生 | 某层 Hidden State |
| 激活函数 | 否，是计算规则 | 写在模型结构中 | GELU、SwiGLU |

激活值随输入变化；权重在普通推理中保持不变。训练时需要暂存许多激活值以便反向传播，推理时不需要完成这一步。

## 总参数量和每 Token 激活参数量

Dense 模型通常让每个 Token 经过同一组参数。MoE 模型拥有多个 Expert，但每次只选择其中少数几个。

- **总参数量**：模型一共保存多少可训练数值；
- **每 Token 激活参数量**：处理一个 Token 时实际参与主要计算的参数规模。

“激活参数”容易与“激活值”混淆，最好说完整的“每 Token 激活参数量”。

## Batch、Step、Epoch 和训练 Token

- **Batch**：一次并行处理的一组训练 Token；
- **Step**：使用一个 Batch 完成一次参数更新；
- **Epoch**：完整遍历一次指定数据集；
- **训练 Token 数**：训练过程中实际处理的 Token 总量。

超大规模训练更常关心训练 Token 总数和计算预算，因为数据可能被重新采样，不一定按整齐的 Epoch 组织。

## 权重中到底保存了什么

准确的说法是：权重编码了有助于降低训练分布预测误差的统计规律，包括语言结构、概念关系、常见事实模式、代码模式和任务格式。

这些规律以分布式方式重叠存在。模型不是先建立事实库，再建立语法模块。

## Checkpoint 是什么

Checkpoint 是训练过程的快照，通常包含模型参数，有时还包含优化器状态、训练步数等恢复训练需要的信息。

用于推理的模型主要需要结构配置、Tokenizer 和权重。Checkpoint 不是“模型的一段记忆”，而是某一训练时刻的完整数值状态。

## Scaling Law 到底意味着什么

Scaling Law 是实验中观察到的经验关系：在一定条件下，增加参数、训练数据和计算量，平均预测 Loss 往往以比较平滑、可预测的趋势改善。

可以抽象写成：

$$
L(N,D,C)
$$

这里只需要读出关系：最终 Loss 与参数量 $N$、数据量 $D$、计算预算 $C$ 共同相关。

### 它告诉我们什么

- 扩大规模通常能改善平均预测能力；
- 参数、数据和计算需要相互匹配；
- 参数很多但训练数据不足，参数可能训练不充分；
- 数据很多但容量或计算不足，也无法充分吸收。

### 它没有告诉我们什么

- 不保证某个具体任务一定提升；
- 不保证事实永远正确；
- 不等于“参数翻倍，智能翻倍”；
- 不解释某个具体回答为何成功；
- 不意味着规模可以无成本无限增加。

> [!important] Scaling Law 是趋势，不是能力保证书
> 它适合估计整体训练趋势，不能证明某次回答正确。

## 为什么会出现看起来突然的能力

能力可能随规模平滑改善，但评测使用“答对/答错”阈值后，看起来像在某个规模突然出现。也有复杂能力需要多个基础能力同时达到一定水平。理解“涌现”时，应同时检查真实能力曲线和评测方式。

## 基础模型得到什么，又缺什么

基础模型通常已经能续写语言、生成代码、表现出常见知识和一定推理能力。但预训练主要教它“什么内容可能接在后面”，并没有稳定规定“用户发出指令时必须以助手身份回答”。

它可能回答问题，也可能继续补写问题、模仿网页格式，或者生成与用户期望不同的角色。这不是 Transformer 坏了，而是训练目标还没有把它塑造成方便交互的助手。
